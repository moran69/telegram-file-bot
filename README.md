# Telegram 频道转发助手

把频道原帖转发给机器人，或发一条消息链接，就能将帖子转存到目标频道。也可以开启自动监听：源频道发新帖时复制一份，之后改文字、说明或更换图片、视频时，更新原来的目标帖，不另发一条。

| 我想做什么 | 怎么操作 | 目标频道会发生什么 |
| --- | --- | --- |
| 转发一条帖子 | 直接发原帖链接，或把频道原帖转发给机器人 | 通过 TDL 转发为新帖，不建立编辑同步关系 |
| 持续同步一个频道 | 配置监听源，或用 `/monitor add` 临时添加 | 自动复制新帖；源帖被编辑后，只更新对应的目标帖 |
| 修正一个已复制的帖子 | 管理面板 → **手动同步** → **回复专用提示**，粘贴源帖链接 | 只更新已有的目标帖；入队回执里有可点击的目标帖链接 |

仅处理你有权读取和转发的内容。自动监听先使用 Telegram 服务端复制。源频道禁止转发时的处理方式取决于部署配置，见下文「让新帖和编辑自动同步」。

## 快速部署

以下命令在 **Linux 宿主机**执行。准备好 [Docker](https://docs.docker.com/engine/install/)、[Compose 插件](https://docs.docker.com/compose/install/) 和 [TDL](https://docs.iyear.me/tdl/zh/getting-started/installation/)。已有部署且原先挂载的是单个 `forward_history.json`？请先看[旧版历史迁移](#旧版历史迁移)，不要直接重建。

**1. 确认工具可用，并登录负责手动转发的 Telegram 账号。** 本项目把宿主机的 `/usr/local/bin/tdl` 和当前用户的 `~/.tdl` 挂进容器；请用同一宿主机用户登录 TDL 和运行 Compose。

```bash
docker compose version
test -f /usr/local/bin/tdl && test -x /usr/local/bin/tdl && echo 'TDL 可执行文件已就绪'
/usr/local/bin/tdl login -T qr
```

**2. 克隆仓库，填写本地配置。** 已有 `.env` 不要覆盖。

```bash
git clone https://github.com/Homomimo/telegram-tdl-forwarder.git
cd telegram-tdl-forwarder
cp -n .env.example .env
chmod 600 .env
nano .env
```

| 配置项 | 填什么 |
| --- | --- |
| `API_ID`、`API_HASH` | 在 [Telegram API development tools](https://my.telegram.org/apps) 获取的应用凭据 |
| `BOT_TOKEN` | [@BotFather](https://t.me/BotFather) 签发的机器人令牌，不是 `API_HASH` |
| `ADMIN_IDS` | 你本人的 Telegram **用户 ID**；多个管理员用英文逗号分隔 |
| `FORWARD_TO_CHAT_ID` | **目标频道**，例如 `1234567890`，也接受标记形式 `-1001234567890` |
| `SUBMITTER_IDS`（可选） | 允许投稿、但不能管理机器人的其他用户 ID。留空时只有管理员可投稿 |

全文用 `9876543210` 表示**源频道**、`1234567890` 表示**目标频道**。例如源帖链接 `https://t.me/c/9876543210/42` 中，`9876543210` 是源频道裸 ID，`42` 是消息 ID。部署时换成你自己的两个不同频道；源和目标相同会跳过同步。仅做手动转发不需要用户 session。其他选项见 [`.env.example`](.env.example)。请勿分享填写后的 `.env`、会话字符串或展开了凭据的 Compose 配置。

**3. 启动并验证。**

```bash
docker compose up -d --build telegram-bot
docker compose logs -f telegram-bot
```

然后用 `ADMIN_IDS` 中的账号私聊机器人：发 `/start` 应看到管理面板，发 `/showto` 应看到你设置的目标频道。

**怎么看启动日志？** 默认日志级别即可，不用开启 DEBUG：

| 日志标记 | 能确认什么 |
| --- | --- |
| `[启动/环境]`、`[启动/配置]` | 实际运行版本、时区、目标及监听源、管理员人数和开关。凭据「已填写」不等于登录成功。 |
| `[启动/存储]`、`[启动/TDL]` | 历史记录条数、映射及队列文件位置、清理周期；仅检查 TDL 是否存在并可执行，不会登录 TDL 或发送测试消息。 |
| `[启动/Bot 登录]`、`[启动/用户监听]` | 区分正在连接、Bot 验证成功，以及用户监听关闭或会话验证情况。登录卡住时，先看最后一条停在哪一步。 |
| `[启动/队列]` | 本次恢复了多少立即任务、定时重试、等待编辑映射及待人工核对的记录；空队列也会显示零。 |
| `[启动/就绪]` | 启动流程已完成，显示实际监听客户端、同步状态、管理员面板送达数及耗时。**不代表已经验证频道读写权限。** |

若只有 Compose 自身的报错，没有 `[启动/环境]`，先看 `docker compose ps -a` 及 `docker compose up` 的报错：变量插值失败或挂载失败时，Python 进程可能根本没启动。分享日志前请遮盖频道 ID 和本地路径；不要分享 `.env`。

## 第一次转发

把一条频道原帖转发给机器人，或直接发送 `https://t.me/channel_name/42`（公开原帖）、`https://t.me/c/9876543210/42`（按频道 ID 定位的原帖）。看到入队提示后，到目标频道核对结果。TDL 登录账号需要能读取源帖并在目标频道发帖。

- **不是文件上传机器人。** 直接从本地发送一张图片或一个视频，如果没有转发来源，也没有附原帖链接，不会入队。
- 如果收到「无法确认原帖」，请复制**原帖本身**的消息链接，不要发频道首页、评论或话题链接。机器人不会猜测来源。
- 批量转发：在面板点「批量转发」，依次回复同一源频道的起止原帖链接，核对目标和范围后确认。这是补发历史消息，不是修正已有目标帖。

## 自动监听与手动同步

### 让新帖和编辑自动同步

1. 在 `.env` 设置 `MONITOR_CHAT_IDS=9876543210`。监听源只填裸 ID，不加 `-100`；多个源用英文逗号分隔。
2. 若使用用户账号监听，先让该账号加入源频道，并赋予它在目标频道发帖及编辑对应帖子的权限。然后运行 `docker compose run --rm gen-session`，按提示登录，将输出的 `USER_SESSION_STRING=...` 填回 `.env`，保持 `USER_MONITOR_ENABLED=1`。**这个字符串等同于登录凭据。**
3. 运行 `docker compose up -d --force-recreate telegram-bot` 载入配置。发 `/monitor` 核对源频道，再发一条测试源帖：先确认它被自动复制，再修改说明，检查**同一条目标帖**是否更新。

Bot 和已连接的用户账号可以同时接收更新。即使只有 Bot 收到了某条新帖或编辑，也会处理；两个账号都收到同一帖时，按源频道、消息 ID 和目标频道去重。新帖优先用收到事件的账号，更新目标帖优先用原发送账号。账号不会共享会话或频道访问凭据。两者都没收到的更新不会凭空补齐，程序不扫描历史。

**普通权限不足不会自动切换到 TDL。** 复制新帖被明确拒绝发帖或访问时，如果另一个监听账号在线，可用它自己的权限重新尝试一次；结果不明时不会换号重发。编辑目标帖失败也不会另发。未配置用户会话时只由 Bot 监听，Bot 需要能接收源频道更新，并在目标频道有发帖和编辑权限。

只有自动复制**新帖**时明确收到 `CHAT_FORWARDS_RESTRICTED`（源频道禁止转发），才会检查 TDL 回退开关。**当前 Docker Compose 与直接运行 Python 的默认值不同**：Compose 在变量未设置或留空时使用开启值；直接运行 Python 时，环境变量未设置或留空则为关闭。显式设为 `0` 时两者均关闭。启动日志中的 `MONITOR_TDL_FALLBACK：开启/关闭` 显示当前进程的实际状态。

回退关闭时，此次复制会报告失败。开启时，自动回退采用 **TDL 下载媒体 → 当前监听账号上传发送**：用 Telegram 返回的 `random_id → 目标消息 ID` 回执建立精确映射，支持后续原地编辑、`/resync` 和目标帖跳转。这里不再直接调用 `tdl forward --mode clone`，因为原版命令不会提供建立映射所需的目标 ID；普通手动转发仍使用该命令，不建立映射。

- **权限分工：** TDL 登录账号需要能读取和下载源媒体；实际发送和后续编辑由 Bot 或用户监听账号执行，该监听账号需要源频道读取和目标频道发帖、编辑权限。TDL 和监听账号不必是同一个账号，但不会借用彼此的频道访问凭据。
- **照片上传：** 普通照片按 JPEG 上传；作为文件发送的图片、视频仍按文档处理。源频道或照片启用内容保护时，只有当前监听账号被 Telegram 确认为源频道所有者才处理照片上传；无法核实权限时，不发布相册，也不替换目标照片。
- **相册不逐条拆发：** 按真实 `grouped_id` 核对源成员，按源消息顺序通过一次相册请求发送，并分别记录各成员映射。每个成员保留自己的说明、文字格式和媒体剧透标记；下载、大小校验或上传准备失败时，不发布残缺相册，也不降级成纯文字。
- **保守处理：** 相册已有投递或待核对成员时，不整组重发，也不把剩余成员拆开发送；回执缺失时只保存确认的映射，其余列为待核对，不自动重发。旧版 TDL `clone` 已发送的消息仍只有去重记录，不会追猜目标 ID 或自动补建映射。
- **运行开销：** 回退和媒体替换需要临时磁盘空间及下载、上传流量；临时文件在任务结束或取消后删除。Telegram 对文件大小、媒体格式和编辑权限的限制仍然适用。

### 手动修正一条已复制的帖子

在管理员私聊点 **「手动同步」**，然后**回复机器人刚发的输入提示**，粘贴 `https://t.me/c/9876543210/42`。如果没有回复提示，而是单独发送链接，就会走普通转发，可能多发一条。

| 看到的回执 | 意味着什么 |
| --- | --- |
| ⏳ 已加入原地同步队列 · 🔗 查看目标帖 | 已受理。点击链接可直接打开对应的目标消息；**入队不是编辑完成** |
| ℹ️ 当前目标没有转发映射 | 找不到这条源帖与当前目标帖的对应记录。不会猜测目标，也不会补发 |

按钮接受 `t.me/c/频道裸ID/消息ID` 形式的**源帖**链接，不接受公开用户名、评论、话题或目标帖链接。也可直接发 `/resync https://t.me/c/9876543210/42`；如果只知道两个数字，发 `/resync 9876543210 42`。

**想让旧帖长期保持同步？** 默认每 7 天清理一次复制确认已满 7 天的映射。清理不删除 Telegram 上的消息，但没有映射后，自动编辑和手动同步都无法再定位旧帖。需要长期同步时，提前在 `.env` 将 `MONITOR_MAP_RETENTION_DAYS` 设得更长，或设为 `0` 永久保留，再重建容器；改设置不能恢复已清理的记录。

## 命令速查

| 用途 | 命令 |
| --- | --- |
| 打开管理面板 / 分步向导 | `/start` · `/help` |
| 查看 / 切换目标 | `/showto` · `/forwardto 1234567890` |
| 查看 / 增删监听源 | `/monitor` · `/monitor add 9876543210` · `/monitor del 9876543210` |
| 替换 / 清空监听列表 | `/monitor set <源ID1,源ID2>` · `/monitor clear` |
| 原地同步已映射的帖子 | `/resync 9876543210 42` |
| 批量转发历史范围（含两端） | `/export_range 9876543210 100 200` |
| 查看队列 / 停止手动任务 | `/queue` · `/tdlstop` |
| 最近 10 条转发记录 / 清空本地记录 | `/flog` · `/flog clear` |
| 重启机器人进程 | `/restart` |

- `/forwardto` 和 `/monitor` 的改动只在本次运行有效；要跨重启保留，请修改 `.env`。切换目标不会改变已入队任务的目标。
- 收到“已加入队列”即表示任务已保存到 `monitor-data`。重启后恢复未开始发送的任务；不确定是否送达的可用 `/queue` 查看，手动投稿和批量发送的逐条错误按源 ID 核对，不自动整批重发。`/tdlstop` 已取消的任务不会恢复。
- 清理映射只对确切投递过的源 ID 去重；旧版已丢失明细的区间标为待核对。`/flog clear` 只清历史，不影响这些记录。
- **回复按钮提示后，看哪里？** 添加监听和手动同步的结果会直接回复在你的输入下方；输入无效、取消或过期也会说明原因。更换目标、替换监听列表，以及填完批量转发的结束链接后，会在输入下方出现确认卡片。看到「待确认」表示还没执行，点「确认执行」后看卡片上的结果；「已入队」不代表转发或同步完成。
- 私聊按钮的输入提示和确认页 5 分钟有效。等待输入时，单独发频道 ID 会收到如何回复的提醒，不会更改设置；单独发消息链接仍按普通投稿处理。回复「取消」可退出输入；重新打开 `/start` 或 `/help` 会使旧面板失效。请直接发送管理命令，不要转发命令消息。
- `/tdlstop` 会停止当前手动 TDL 任务，清空当时等待中的任务和定时重试；不会撤回已发消息，也不强停正在执行的自动同步。`/flog clear` 不删除频道帖子或编辑映射。

## 常见问题

| 现象 | 先检查什么 |
| --- | --- |
| `PHOTO_EXT_INVALID` / `The extension of the photo is invalid` | 旧版把普通照片命名为 `.bin`。更新并重建容器后，照片会用 `.jpg` 上传。如果仍然报错，请按日志中的源消息 ID 核对；此错误发生在发布或编辑之前，不必清空映射库。`/resync` 只适用于已有目标帖的情况。 |
| 手动转发正常，自动监听却没有新帖 | 用 `/monitor`、`/showto` 核对源和目标；确认 Bot 或用户监听账号确实收到了更新并有发帖权限。若提示“频道实体尚未就绪”，任务已保留，重启或同源新更新会再次尝试。若提示“未能持久化”，按告警中的消息 ID 核对，并检查数据卷空间和写入权限。 |
| 文字更新了，但附件没有更换 | 原地替换支持照片、视频以及以文件形式发送的普通图片和视频；其他附件只同步文字。相册按成员更新。若 Telegram 拒绝替换，不会删除原帖重发 |
| 目标帖还在，手动同步却提示没有映射 | 确认提交的是**源帖**，且目标频道未切换。手动 TDL 转发不建立映射；映射过期或数据卷被删除也会导致这种情况 |
| 更改 `.env` 后仍提示 Token 无效 | 核对 `BOT_TOKEN` 是否为 BotFather 签发的有效令牌，然后执行 `docker compose up -d --force-recreate telegram-bot`。仅 `restart` 不会重新载入 `.env` |
| 日志提示转发历史损坏 | 在 `./history/` 查找程序保留的 `.corrupt-*` 备份，先核对再处理。转发历史与同步映射是两份数据，不要为修复历史而删除 `monitor-data` |

## 运维与数据

| 数据 | 保存在哪里 | 用途 |
| --- | --- | --- |
| 转发历史 | `./history/forward_history.json` | `/flog` 显示近 7 天内最近 10 条，过期记录在下次保存时从文件移除 |
| 同步映射 | `monitor-data` 卷中的 `/data/monitor/message_map.sqlite3` | 记录源帖对应的目标消息 ID，并持久保存 TDL 克隆去重记录（不参与每周清理）。重建容器时保留此卷；**不要用 `docker compose down -v` 停服** |
| TDL 账号会话 | 宿主机 `~/.tdl` → 容器 `/root/.tdl` | 手动转发及自动回退下载使用。保护目录权限，不要提交或分享 |

日常停服用 `docker compose down`；更新源码后用 `docker compose up -d --build telegram-bot`；查看最近日志用 `docker compose logs --tail=100 telegram-bot`。常规更新不需要禁用构建缓存。

<details>
<summary>相册、重试与临时消息的处理规则</summary>

- 自动监听优先整组复制相册；从首个成员起等 1 秒仍没收到整组事件，就先复制实际收到的成员。晚到的成员可能单发，不按相邻 ID 猜测遗漏消息。
- TDL 回退额外查询已知成员前后各 100 个消息 ID，只选择源频道中实际具有相同 `grouped_id` 的成员；不是把连续 ID 当作成员。成员触及边界、缺少已观察到的成员、少于 2 条或多于 10 条时拒绝发送，异常大跨度或无法核对的相册需要人工检查，不能保证任意异常分布均可补齐。
- 同一帖子反复编辑时合并排队；明确限流后保留重试时间，重启不会丢掉最新修改。若上次编辑中断或回执不明，会先比较源帖和**已映射的目标帖**，只更新有差异的内容，不另发新帖。已清理映射的旧帖不占用等待回执的编辑名额。
- 自动入队遇到存储故障最多再试两次；仍失败则合并通知管理员，列出源消息 ID。复制回执先落库，再发送状态通知；即使通知时停服，已确认成员也不列入 `/queue` 的待核对项。
- 若 Telegram 可能已收到复制请求，但没有返回完整回执，会保留未确认记录供核对，不自动重发。不要为了重试手动删除这些记录。
- 默认在任务结束后清理机器人状态消息：普通状态 300 秒、错误状态 600 秒，普通命令回复 120 秒。管理员的启动面板和帮助保留。可在 `.env` 设置 `AUTO_DELETE_BOT_MESSAGES=0` 关闭自动删除，或通过 [`.env.example`](.env.example) 分别调整时长。

### 旧版历史迁移

仅适用于以前把 `./forward_history.json` **作为单个文件挂载**的部署。在原 Compose 项目目录执行；如果目标文件已经存在，请先人工核对，不要覆盖。保留原文件以及 `monitor-data` 卷。

```bash
docker compose stop telegram-bot
mkdir -p history
if [ -f forward_history.json ] && [ ! -e history/forward_history.json ]; then
  cp -p forward_history.json history/forward_history.json
fi
docker compose up -d --build telegram-bot
```

旧 Compose 中如有明文凭据，先迁到本地 `.env`。若凭据曾进入公开仓库或共享镜像，请轮换 Bot Token，并撤销已暴露的用户会话。
